# 0022: The realistic base character is generated with MakeHuman by script

Status: Accepted
Date: 2026-11-27
Issue: [#72](https://github.com/TMHSDigital/Open-Game-1/issues/72)
Supersedes: none

## Context

Decision 0021 set a realistic art direction, with dismemberment later. The current base character is built from scratch by `Art/Characters/Base/build_base_character.py` with a skin modifier over a node graph. It is reproducible and fully ours, but it has no realistic detail, and the 2026-11-27 play-test showed its proportions are off: oversized head, long forward neck, narrow sloped shoulders, limbs with no joint shape.

The source of a realistic character is limited by three facts. The repository is public and holds no Epic content, so MetaHuman assets cannot be committed. The asset pipeline is scripted: everything is rebuilt headless by script and checked. And dismemberment later needs a mesh that can be split cleanly at the joints.

## Decision

The realistic base character is generated by script in Blender with MPFB2 (the MakeHuman plugin), from MakeHuman's CC0 assets, and then modified freely by our own scripts (proportions, anatomy, splitting for dismemberment, skin). Before the generated mesh is committed, its export license is confirmed with the MakeHuman project and recorded in the asset ledger through the asset-import process.

## Consequences

- A realistic human with sound topology, proportions and skin is generated rather than modelled by hand, and stays reproducible: the generating script, its parameters and our modifications are in the repository.
- MPFB2's code is GPLv3 and its bundled assets are CC0. MakeHuman grants CC0 for exports from its official application, but no statement was found for exports made by MPFB2 inside Blender. The license must be confirmed before the mesh is committed. If it cannot be, the fallback is to rebuild our own scripted body (the alternative below).
- The generated mesh is ours to modify. Proportions and anatomy are adjusted by our scripts, and the mesh is cut into pieces at the joints that can come off when dismemberment is built.
- MakeHuman's skeleton is not the UE5 humanoid layout the project uses (`skeleton_reference.json`). The mesh is rigged to (or retargeted onto) the project's 89-bone UE5 layout, so the physics asset, sockets, animation graph and every code path that names bones keep working.
- MPFB2 is a Blender extension that has to be installed on the build machine. The build documents the version used, and the pytest suite skips the build when it is missing, as it does for Blender now.
- The current scripted body stays until the new one works in the game: in the tests, the play-tests and a development build.

## Alternatives

- Rebuild our own scripted body with realistic proportions and anatomy. Rejected as the main path: fully ours with no license question, but realistic detail (skin, face, hands) is very hard to reach with a skin modifier. Kept as the fallback if the MakeHuman license cannot be confirmed.
- MetaHuman. Rejected: the most realistic option, but it is Unreal EULA content that cannot be committed to the public repository, and it is heavy to run with many characters.
- A licensed or commissioned realistic model. Rejected for now: it costs money and needs a license that allows a public repository, and it is not reproducible by script.
