# 2026-11-24-03: Run game-design-versus to pin down what kind of game Combat Simulator is

## Narrative

This session was a design interview instead of a build. The owner answered a long this-or-that questionnaire, run with the game-design-versus tool, where each question sets two or three existing games side by side on one design axis: how the player is embodied, how combat is simulated, how a session is structured, what carries over between sessions, and so on. The tool turned the answers into a seed design brief with a frame, pillars, a core loop, a systems table, risks and a list of questions that are still open.

The brief and the individual answers stay local: `docs/design/` is now ignored, because the brief is a working document and not a record of what the project has committed to. What it settled, in general terms, is that Combat Simulator is a single-player sandbox in which the player directly controls one fighter and combat is the whole point, with everything else that was on the table either ruled out or left for much later. Several of its sections are thin or guessed by the tool, so it is treated as a starting point.

Nothing was decided formally. The points that matter will be opened and closed as numbered decisions as the work reaches them, and those stay public as before. Next is to start building toward the brief, beginning with a decision on the first block of work after decision 0015.
